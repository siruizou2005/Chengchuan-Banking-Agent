# 飞书 Bot 优化实施报告

实施日期：2026-10-13。依据：`techdocs/wxAgentbot_unified_techdoc.md` 的通用可靠性要求及[飞书 Bot 技术检查报告](飞书Bot技术检查报告.md)。

本次已实现飞书消息持久化、绑定生命周期隔离、投递状态管理和 App 结果入口。**用户扫码自动创建自己的专属 bot、自动配置回调并发布的流程保持不变**，共享机器人的 WebSocket 接入也继续保留。

## 1. 交付内容

| 检查发现 | 实施结果 |
| --- | --- |
| 解绑后在途请求仍可写入或回复 | 飞书执行加入绑定状态、授权、会话和代次校验；解绑撤销排队任务、中止执行与发送，旧回调不能继续提交业务结果。已发出的网络请求无法撤回，未确认的投递保留为 unknown。 |
| 重新绑定复用旧身份与上下文 | 每次重绑递增代次、创建新会话并恢复有效授权；旧任务、旧回调及旧通知不能跨代次执行。 |
| 回复忽略平台业务错误 | 统一校验 SDK 返回业务码；明确限流可退避重试，明确拒绝记录失败，网络超时或响应不完整记为 unknown，不自动重复发送。 |
| 收件确认后无法恢复请求 | 新增加密收件表，先持久化再确认；重复消息不会重复运行模型。重启恢复未开始请求，对已经运行但中断的请求保存可解释结果，不自动重新执行业务。 |
| 取消状态被在途发送覆盖 | 投递使用租约与代次校验，条件更新原有 outbox；迟到的成功或失败不能恢复已取消任务。 |
| 慢请求缺少反馈 | 超过默认 4 秒仍未完成时，发送一次等待或处理中提示；快速完成省略提示，每用户最多保留 3 个普通待处理请求。帮助、确认及取消命令单独处理。 |
| 单个发送阻塞其他用户 | 执行与发送分别使用有界并发；同一绑定按投递顺序发送，其他绑定可以继续处理。 |
| 结果缺少补查入口 | 渠道页新增最近飞书请求，结果页支持登录后继续打开；投递失败时通过 App 保留结果与通知。接口限制为请求所属用户。 |
| 回复可能展示过期操作状态 | 发送和查看结果时刷新操作状态；已取消的提议不会继续提示确认。发送时应用用户当前的飞书金额隐藏设置。 |

主要实现位于 `server/channels/feishu-pipeline.mjs`、`feishu-schema.mjs`、`feishu.mjs`、`router.mjs` 及 `server/agent/execution.mjs`。前端新增 `src/pages/FeishuRequests.tsx`，复用渠道结果页。

## 2. 扫码创建流程的保留与验证

原有流程仍为：App 完成 PIN 授权 → 展示创建二维码 → 用户用飞书扫码 → 自动创建专属应用 → 自动配置 webhook → 发布应用 → 激活本人绑定。无需用户手工填写应用凭据。

测试覆盖首次创建、同一飞书身份重新扫码创建、新凭据及新会话生效、旧回调密钥失效。移动端浏览器检查覆盖二维码展示、模拟扫码后自动配置与发布，以及创建后的请求结果展示。

另外使用项目实际安装的飞书 SDK 验证了加密 webhook 的签名校验、解密、有效事件接收及重复事件去重。应用注册和消息投递使用测试替身，未连接真实飞书账号。

## 3. 数据与配置

- 数据库启动迁移新增 `feishu_inbox`、`feishu_deliveries`，并为原有 `channel_outbox` 补充绑定会话和代次字段；保留既有绑定和业务记录。
- `CHANNEL_SECRET` 用于加密渠道凭据和收件、投递正文；共享飞书链路也需要配置。现有部署应继续使用原密钥，不能直接替换，否则已有密文无法解密。
- `FEISHU_PROGRESS_AFTER_MS=4000` 控制等待提示阈值，`FEISHU_FEEDBACK_ENABLED=true` 控制是否启用。默认策略与当前微信实现一致，不将此阈值表述为技术文档原始要求。
- 专属 bot 继续使用 `FEISHU_PERSONAL_ENABLED` 及 HTTPS `PUBLIC_ORIGIN`。相关说明已同步至 `.env.example`、`README.md` 和 `docs/API.md`。
- 新增本人请求接口：`GET /channels/feishu/requests`、`GET /channels/feishu/requests/:id`。

## 5. 验证边界

本次未部署到生产、未修改实际渠道配置或业务数据库、未调用真实模型或发送真实飞书消息。真实租户扫码创建、发布权限、公网回调可达性及终端收信仍需在部署环境联调。

`api_accepted` 仅表示平台接口接受，不表示用户已读；`unknown` 保留待核查状态和 App 结果，不能据此自动重新执行业务。本次验证范围为现有单机 SQLite 架构，未验证多实例部署。
