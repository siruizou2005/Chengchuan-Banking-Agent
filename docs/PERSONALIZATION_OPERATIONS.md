# 个性化部署与验收

运行时要求 Node 24+。沿用原启动、构建和部署方式，无新增服务或数据库依赖。

## 迁移与回退

1. 用原部署脚本的SQLite在线备份保留数据库；不能只复制运行中的主文件而遗漏WAL。
2. 首次启动执行增量事务迁移。旧 agent_memory 行保留原值和更新时间，状态为 candidate。只有用户确认后才用于个性化。
3. 验证已登录用户 `/api/agent/memory`、一次原银行业务查询和各渠道绑定。没有Bot来源的旧飞书共享绑定需用App支付密码解绑后重新绑定；不根据昵称或消息自动迁移身份。
4. 紧急停用个性化可设 `PERSONALIZATION_ENABLED=false` 并重启。用户仍能查看和删除记忆。支付和原金融授权规则不变。
5. 不直接将旧程序连接到已迁移数据库：旧 remember 使用不带列名的 INSERT，新增列后不兼容。需要完整代码回滚时，在维护窗口停止服务并恢复迁移前在线备份；确认备份后新增业务数据的保全方案。优先使用功能开关回退，无需恢复数据。

单库单银行，租户固定为 bank。多进程共享SQLite文件，可共享请求去重、配额、并发与记忆版本；多个独立数据库不共享这些控制。

## 实际24小时空闲审计

本地自动测试使用模拟时间、模拟模型/渠道，不代表实际24小时或真实手机验收。下面的审计需要在实际部署后运行。

1. 等待已受理的用户任务结束。保留正常银行维护和渠道轮询。不要运行 smoke-live/check-agent-live/check-asr 等人工实测脚本。
2. 在服务环境设置 BANK_DB 为实际数据库路径。运行 `node scripts/audit-idle.mjs start /安全路径/idle-baseline.json`。文件已存在时拒绝覆盖。
3. 保持服务连续运行24小时以上，不发送聊天、语音请求，不授权新的模型任务。记录起始和结束的服务启动时间、重启日志；确认同机无其他模型调用程序。
4. 运行 `node scripts/audit-idle.mjs check /安全路径/idle-baseline.json`。仅观察时长至少24小时、无新增模型请求、无待处理用户队列时 passed=true。退出码1表示条件未满足；异常退出码表示证据不完整。
5. 保存输出，并在供应商用量面板核对相同时间窗口的请求数为0。数据库审计只覆盖本服务，无法证明其他进程或外部服务没有调用模型。

inference_calls 仅保存来源、请求/步骤编号、模型、状态、token与费用，不保存提示词和凭据。未知超时记录 unknown，不自动改投其他模型。费用依赖管理员填写真实单价和供应商usage，缺失时为null。单价币种由供应商配置决定。

## 验证命令

- `npm test`：原业务、渠道、记忆与推理测试，全部使用模拟上游。
- `npm run build`：TypeScript检查及前端构建。
- `node scripts/check-personalization-ui.mjs`：另行安装Playwright，设置 PLAYWRIGHT_PACKAGE 指向其 package.json；默认使用本机Edge，可通过 BROWSER_CHANNEL 更改。使用临时内存数据库，截图保存在 test-results。

真实微信/飞书消息收发、部署供应商兼容性与24小时窗口需在配置好外部服务后另行验收。本次本地测试不发送真实渠道消息或真实模型请求。
