# 演示数据与账单口径

演示账户、流水来源与处理方式、账单统计规则和资金业务边界。

| 邹瑞 | 18662995523 | Bank123456 | 123456 | 6218805061407941684 |
| 万奇 | 15040147842 | Bank123456 | 123456 | 6218807752838722169 |

运行中的系统（`server/index.mjs`）只有这两个演示账户，手机号是随机生成的，不会向它们发送真实短信或邮件。这两个账户的账号密码是公开的，所以不做按账户的登录锁定，登录密码和支付密码也不能修改，避免一位访客影响其他人。支持自行注册其他模拟用户，注册不发送短信。请勿使用真实身份、银行卡或密码。

两个账户的流水来自真实对账单（`server/seed/demo-accounts.json`，由 `scripts/build-demo-accounts.mjs` 生成，首次启动时只导入一次）。户名已改，卡号是模拟的，对方账号和附言里的长数字已打码。个人之间转账的对方和个人收款码上的姓名都已换成化名，账号全遮；公司和学校保持原名：

- 邹瑞：建设银行 2025-11-01—2026-11-01 共 503 笔，另加 2026-10-01 的 15 万元本人他行转入，2026-10-17 用 5 万元申购南方天天利货币B 的持仓，以及 2026 年 7—10 月每月 14 日的三笔演示订阅扣款（视频会员 25 元、音乐 15 元、云盘 21 元），这三个订阅也会登记为有效的代扣授权。
- 万奇：工商银行 977 笔，原始日期 2025-10-02—2026-09-29，整体后移 31 天，现为 2025-11-02—2026-10-30，另加 2026-10-01 的 15 万元本人他行转入。

15 万元转入、5 万元申购和订阅扣款是为了演示加的，不在原对账单内，流水的 `source_detail` 有标注，转入不计入收入。持仓只存本金，收益由系统按基金真实净值逐日计算。

数据库第一次以这种方式启动时会执行一次 `demo-accounts-v3`：**清空所有用户及其全部数据**（对话、记忆、渠道绑定、审计等），只保留基金产品缓存等共享数据，然后重新导入这两个账户。

测试和检查脚本默认仍用 `createBank(path)` 的 fixtures 模式，账户是林知夏、陈屿和 `server/seed/fixture-statements.json` 里的流水，不用于运行中的系统。

导入流水在 `ledger` 上另有一组跨银行统一的字段，本行原生流水这些字段为空：

| 字段 | 含义 |
| --- | --- |
| `txn_type` | 统一交易类型：消费 / 退款 / 转出 / 转入 / 本人转出 / 本人转入 / 充值 / 提现 / 缴费 / 理财申购 / 理财赎回 / 利息 / 存现 / 期初余额 |
| `bank_summary` | 原银行摘要（如建行「跨行转出」、工行「无卡支付」） |
| `counterparty` / `counterparty_account` | 对方户名 / 对方账号（脱敏） |
| `merchant` | 商户或交易对象；工行只显示支付宝、财付通等支付机构时为空 |
| `platform` | 支付平台：支付宝 / 微信支付 / 京东支付 / 抖音支付 / 银行；无法判断时为空 |
| `channel` | 原银行渠道（工行：快捷支付、网上银行、手机银行等；建行对账单无此项） |
| `memo` | 附言或交易地点（建行） |
| `time_precision` | `second` 为精确时间；`day` 表示原对账单只有日期，时间统一记为北京时间 12:00 |
| `source_bank` / `source_detail` | 来源银行 / 其余原始字段的 JSON（序号、币种、钞汇、储种、地区） |

### 账单分析口径

`server/agent/analytics.mjs` 给每条流水（导入与本行原生）计算 `kind` 和显示分类 `tag`，交易记录页、导出、智能体统计共用同一套规则，日期一律按北京时间归属：

- `kind`：consumption 消费、refund 退款、income 收入、transfer_out 转账给他人、self 本人账户互转、wallet 充值提现（微信零钱/支付宝余额）、investment 理财存款、debt 信用卡/贷款、opening 期初余额。
- 消费 = 消费 − 退款，退款冲减到同一分类；转账给他人单列；本人账户互转、充值提现、理财存款、信用卡/贷款不计入消费；期初余额和演示开户资金不计入收入。
- 消费分类采用 CHFS 8 大类：食品、衣着、居住、家庭设备及服务、交通通信、教育文娱、医疗保健、其他消费。另有个人收款码（小商户的个人收款码）和支付宝支出、微信支付支出等平台支出。导入行按商户、对方户名、附言匹配，原生行按标题匹配。
- 优先级依次为：单笔手动修改、本人同商户规则、关键词、模型缓存、其他消费。只命中平台词（淘宝、京东、商贸等），或同时命中多个大类，都算拿不准，归入其他消费。店名里的地点（如某大学店）和“交通银行”不算依据。这些都只改变分类，不影响消费总额和风控。
- 设置 `BILL_CATEGORY_LLM=true` 后，每天北京时间 03:00 把其他消费的商户名去重，每批最多 50 个（`BILL_CATEGORY_BATCH_SIZE`）发给 `CHAT_MODEL` 分类，结果写入全局缓存 `merchant_categories`，同一商户只问一次。模型看不出业务时保持其他消费，90 天后再试。失败每 30 分钟重试，每天最多 3 次，运行记录在 `merchant_category_runs`。只处理已同意当前协议且数据读取授权有效的用户。只发商户名，人名（含复姓、带点的姓名、拼音和“给某某”这类写法）、掩码和带分隔符的长数字都不发，这是启发式过滤，自由填写的商户名不能保证全部识别。关闭开关或缺配置时，重试也不会发送。
- 「支付宝支出」「微信支付支出」是原银行只显示支付宝、财付通等支付平台、看不到真实商户的部分（万奇约六成），卡片会注明；平台也无法判断时归为其他消费。

聊天展示规则：每次回答最多一张统计卡片（`bill_report` / `spending_stats` / `detect_anomalies` 三选一，服务端拒绝同一轮的第二张），文字只写两三句结论。分类和支付平台用环形图（最多 5 个色块加「其他」），商户用排行，按日/周/月/星期/小时用柱状图；点色块、分类、商户或柱子会在卡片内展开对应流水，并可跳到带同样筛选条件的交易记录页。卡片底部给出两三个「接下来可以看」的追问，点一下即发送。新回复到达时停在该回复的开头。

智能体统计工具（均为绿色只读，时段参数统一为 `preset` / `period` / `from`+`to`）：

| 工具 | 用途 |
| --- | --- |
| `bill_report` | 日报、周报、月报、年报或任意区间：消费、转账给他人、收入、分类占比、商户 Top5、收入来源、不计入消费的资金往来、按日/按月趋势、环比与数据覆盖；卡片拿完整报告，模型拿 4KB 内的精简版 |
| `spending_stats` | 按分类 / 商户 / 支付平台 / 月 / 周 / 日 / 星期 / 小时统计，可限定分类、商户关键词或类型；只有日期的流水不参与按小时统计 |
| `get_ledger` | 按时段、方向、类型、分类、关键字查看明细，结果裁剪到 4KB 内 |
| `detect_anomalies` | 大额、深夜、首次大额、24 小时同额重复，最多 10 条 |
| `run_analysis` | 沙箱内自定义统计，`data.ledger` 已带 `kind`、`tag`、`bj_time` |

`preset` 取值：today、yesterday、this_week、last_week、last_7_days、last_30_days、this_month、last_month、last_3_months、this_year。`period` 和 `from`+`to` 只接受 2000 年至明年的日期，跨度不超过 10 年。


## 业务规则与边界

基金名称、净值与业绩取自东方财富公开数据，仅用于展示和分析；其余资金、银行、商户、存款产品和账单均为模拟数据，申购不发生真实交易。跨行转账流向模拟清算账户，不接入真实银行。存款按年利率逐日计息（算头不算尾：含存入当日，不含到期或支取当日；到期后停止，提前支取按实际持有天数计息），基金按每日净值变动计算收益，都在用户读取持仓或赎回时按需结算，赎回时本金和收益按比例到账；不计手续费或税款；固定持有期理财到期前不可赎回。贷款以 20 万元虚拟额度自动审批，只记录本金借还。信用卡汇总待还本金，不生成真实账单周期、分期、利息或征信。客服只保存工单，无真人回复。人脸验证为摄像头采集本地画面摘要的演示模拟，不做生物识别；短信验证码投递到站内消息中心，不发送真实短信。

这是一套可运行的个人零售银行模拟基础，不包含真实银行的合规身份验证、清算对账、反洗钱、对公业务、外汇、保险、证券交易或生产级高可用系统。

## 交易与数据

金额请求使用**人民币元字符串**，例如 `"100.50"`；返回数据统一使用**整数分**。创建交易时使用幂等键，扣款交易先预留余额；输入支付密码确认后，SQLite 事务内完成双边资金流水与业务更新。确认前重新检查账户、持仓及额度。失败、取消、过期释放预留资金。每 30 秒的维护任务清理过期交易与动作、执行到期的定时转账、计划步骤、订阅代扣、续费提醒和锁定释放；请求时也会立即检查。重复确认不会重复入账。

用户资源均验证归属。密码用独立盐 scrypt 哈希，会话仅保存 token 哈希；浏览器使用 HttpOnly Cookie，API 支持 Bearer Token。登录失败按 IP 和手机号分别计数，成功登录只清该手机号的计数，支付密码和验证码失败按用户计数，都是进程内限频。正式域名使用 HTTPS Secure Cookie、严格来源校验及仅信任本机代理。完整资金总账平衡检查（含演示流水与订阅代扣）包含在自动化测试中。
